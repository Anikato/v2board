# 企业账号（组织席位）设计

- **状态：** 草案，已锁定主路径，细节待讨论
- **日期：** 2026-09-20
- **范围：** Anikato/v2board fork（不上游）
- **前端：** 企业管理员界面做在 x-user；本面板只提供 API。默认主题 / 后台 `umi.js` 无源码，不改编译产物。

## 1. 要解决什么

企业买一份套餐，由一名企业管理员（同时是可使用的普通用户）在前台**手动添加**本公司员工账号。员工各自登录、各有订阅 UUID。流量和设备按套餐写到每个账号上，**没有企业流量池 / 设备池**。到期跟主账号；不用的人由企业管理员暂停。续费不走网站前台，由超级管理员在后台改主账号。

## 2. 明确不做

- 企业共享流量池、共享设备池
- 邀请码注册自动变子账号（与现有返佣邀请分开，避免语义冲突）
- 企业管理员改流量、设备、速度、套餐、到期时间
- 企业管理员 = `is_staff` / `is_admin`（staff 能管全站）
- 空壳「只能管理不能上网」的管理员账号
- 改 v2node / 节点协议 / `TrafficFetchJob` / 按用户的设备统计
- 企业前台自行购买或续费（可在后续打开，默认关）

## 3. 术语

| 词 | 含义 | 不是 |
|---|---|---|
| 主账号 / 企业管理员 | `org_role = owner` 的 `v2_user`，自己能用网，并能管本公司子账号 | `is_staff`、`is_admin` |
| 子账号 | `org_role = member`，`org_id` = 主账号 `id` | 邀请返佣用户 |
| 席位 | 主账号允许存在的子账号数量上限（暂停中的仍占席位） | 套餐的 `capacity_limit`（那是「这个套餐还能卖几份」） |
| 暂停 | 子账号 `banned = 1`：不能登录、不下发到节点 | 删除账号、改到期时间 |
| 企业一份订阅 | 钱和到期只记在主账号；子账号 `expired_at` 始终等于主账号 | 全公司共用一条客户端订阅链接 |

每个子账号仍是完整的 `v2_user`（独立 email、密码、uuid、token、`u`/`d`、`transfer_enable`、`device_limit`）。节点侧继续按单用户判断，无需改协议。

## 4. 关系

```
超级管理员（is_admin）
  └─ 给某用户开通企业套餐，标成主账号，设定席位
       └─ 主账号（普通用户 + 管理权，付费/到期主体）
            └─ 子账号 × N（手动添加；额度从套餐抄来；到期 = 主账号）
```

席位算法（推荐，待确认）：`子账号数 <= org_max_seats`，**主账号不计入子账号名额**。例如名额 10 = 主账号自己用 + 最多 10 个员工。

## 5. 数据

不新建「组织表」。主账号就是组织。

`v2_user` 增加：

| 字段 | 类型 | 说明 |
|---|---|---|
| `org_id` | int NULL | 子账号指向主账号 `id`；主账号、普通用户为 NULL |
| `org_role` | tinyint NULL | NULL 普通用户；`1` owner；`2` member |

席位上限放哪（**待讨论，见 §11**）：

- 方案 P：`v2_plan.org_max_seats` + 可选 `v2_plan.is_enterprise`
- 方案 U：`v2_user.org_max_seats` 只写在主账号上

索引：`org_id`。添加子账号时对主账号行加锁，按 `org_id` 计数，避免并发超员。

不把额度再存一份到组织上：流量、设备、速度、节点组仍是每个用户自己的字段，开通/同步时从套餐抄到用户，与现有 `OrderService::buyByPeriod` 一致。

## 6. 规则

### 6.1 开通与到期

- 超管给主账号设定 `plan_id` 并写入 `expired_at`（后台改用户，或走订单开通——企业默认不走前台下单）。
- 同步范围：该主账号下所有子账号（含已暂停的）。
- 同步字段：`plan_id`、`group_id`、`transfer_enable`、`device_limit`、`speed_limit`、`expired_at`。
- **不**同步：`banned`（暂停状态由企业管理员管）、email/密码/uuid、`u`/`d`（个人已用流量）。
- 主账号 `expired_at` 过期后：主账号和子账号都不下发到节点；主账号**仍可登录**做管理；已暂停的子账号仍不能登录。

必须接上的同步入口（企业续费走这里）：

1. 超管后台 `Admin\UserController@update`：改的是主账号的 `expired_at` 或 `plan_id`
2. 若有订单把套餐写到主账号（`OrderService`），同样同步

只改主账号、漏同步，子账号会按自己旧的 `expired_at` 继续用网。这是本功能最容易出的洞。

### 6.2 添加子账号（仅企业管理员手动）

1. 调用者必须是 `org_role = owner` 且未封禁。
2. 主账号必须有有效套餐（`plan_id` 有值）。到期后是否仍允许加人：**建议允许**（只是加出来也暂时不能用），待确认。
3. `count(org_id = 主账号id) < 席位上限`，否则拒绝。
4. 创建用户：独立 email、初始密码（管理员指定或系统生成后返回一次）、新 uuid/token。
5. 从主账号当前套餐抄额度与 `expired_at`，`org_id` / `org_role = member`，`banned = 0`。
6. 子账号 `invite_user_id` 可记主账号，**不算返佣**（下单会被拒绝，见 6.4）。

企业管理员不能：改任何账号的流量/设备/速度/套餐/到期；把某人加成 `is_admin` / `is_staff`；操作其他公司的用户。

### 6.3 暂停 / 恢复 / 删除

| 动作 | 谁 | 实现 | 席位 |
|---|---|---|---|
| 暂停 | 企业管理员 | 子账号 `banned = 1`，并清该用户会话（与超管封禁相同，`AuthService::removeAllSession`） | 仍占用 |
| 恢复 | 企业管理员 | `banned = 0` | 仍占用 |
| 删除 | 企业管理员或超管 | 删 `v2_user`（需处理订单/工单等现有删除逻辑） | 释放 |
| 暂停自己 | 禁止 | — | — |

暂停不改 `expired_at`。主账号续期后，未暂停的子账号自动可随新到期时间用网；暂停中的保持暂停。

### 6.4 购买与续费

- 子账号：拒绝创建订单、拒绝 checkout、拒绝礼品卡开通套餐。
- 主账号：默认也拒绝前台购买/续费；开通与延期只走超管后台。
- 普通用户：行为不变。

### 6.5 节点与流量（不改协议）

现有条件已足够：

- `getAvailableUsers`：`banned = 0` 且 `u+d < transfer_enable` 且 `expired_at` 有效
- 登录：`banned` 则拒绝（暂停的子账号进不了面板）
- 设备：各用户自己的 `device_limit`，节点上报 `ALIVE_IP_USER_{id}`

主账号到期或子账号暂停后，最多等到节点下一次拉用户列表生效（与现在封禁/到期相同，通常几十秒到几分钟）。

流量重置：每个子账号仍按套餐的 `reset_traffic_method` 各自清 `u`/`d`。企业没有总池，互不影响。已用流量不同步、不汇总到主账号（只读统计若要做，是查询聚合，见 §11）。

## 7. API（草案）

前缀 `/api/v1/user/org/…`，中间件 `user`，控制器内校验 `org_role === owner`。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/user/org/info` | 席位已用/上限、主账号到期、套餐名 |
| GET | `/user/org/members` | 本公司子账号列表（邮箱、banned、已用流量、到期；**默认不返回 uuid/token**，防管理员直接把别人的订阅发出去——是否允许「查看/重置订阅」见 §11） |
| POST | `/user/org/members` | 添加：email、password |
| POST | `/user/org/members/ban` | 暂停 `{ id }` |
| POST | `/user/org/members/unban` | 恢复 `{ id }` |
| POST | `/user/org/members/reset-security` | 重置该子账号 uuid/token（可选） |
| POST | `/user/org/members/drop` | 删除（可选，一期可只做暂停） |

超管后台（现有 `Admin\UserController` 扩展，不必新后台页也能用）：

- 将用户标为 owner、取消 owner（须无子账号或先处理完）
- 改席位上限（若采用方案 U）
- 改主账号套餐/到期 → **触发子账号同步**
- 筛选 `org_id` / `org_role`

`GET /user/info` 增加只读：`org_role`、`org_id`，供 x-user 显示「企业管理」入口。

## 8. 权限对照

| | 超级管理员 | 企业管理员 | 子账号 | 普通用户 |
|---|---|---|---|---|
| 用网（未过期未暂停） | 视其套餐 | 是 | 是 | 是 |
| 添加/暂停本公司子账号 | 可在后台代做 | 是 | 否 | 否 |
| 改流量/设备/到期 | 是 | 否 | 否 | 否 |
| 前台续费 | — | 否（默认） | 否 | 是 |
| 管其他企业 | 是 | 否 | 否 | 否 |

## 9. 关键代码挂钩

| 点 | 文件 | 做什么 |
|---|---|---|
| 超管改用户 | `Admin\UserController@update` | 目标是 owner 且改了 plan/到期 → 同步子账号 |
| 订单开通 | `OrderService` `buyByPeriod` / `buyByOneTime` | 若 user 是 owner，同步子账号（防御性；默认企业不走前台单） |
| 下单 | `User\OrderController@save` | member 拒绝；owner 默认拒绝 |
| 登录会话 | 暂停时 `AuthService::removeAllSession` | 与超管封禁一致 |
| 节点下发 | `ServerService::getAvailableUsers` | 不改（靠 banned + expired_at） |
| 注册邀请 | `Passport\AuthController` | **不**把邀请用户收成子账号 |

新增：`OrgService`（添加、计数、同步、权限），`database/update.sql` 加列。

## 10. 分期

**一期（建议先做这些）：**

- 迁移字段
- `OrgService`：同步到期/套餐、席位计数、添加、暂停/恢复
- 企业管理员 API
- 超管把用户标成 owner，改主账号到期时同步
- 子账号/主账号前台下单拒绝
- x-user：成员列表、添加、暂停

**一期不做：** 删除子账号、重置别人订阅、流量汇总看板、企业套餐商品化前台、邀请入组。

## 11. 待讨论细节

下面这些不影响「要不要做」，但会定字段和 API 形状。文档先记下推荐值。

1. **席位上限存在哪**  
   - P：套餐字段，改套餐则所有用该套餐的企业一起变。  
   - U：写在主账号上，同套餐不同公司可以不同名额。  
   - 推荐：U，超管按合同填；套餐上可给默认值作参考。

2. **主账号占不占席位**  
   - 推荐：不占。名额 = 可添加的子账号数。

3. **一期是否允许企业管理员删除子账号**  
   - 推荐：先只暂停。删除要处理订单/工单/统计，且不可逆。腾席位由超管删，或二期再做删除。

4. **企业管理员能否看/重置子账号的订阅链接**  
   - 能看：方便代配客户端，但等于能冒用员工订阅。  
   - 只能重置、不能读旧 token：更安全，员工要自己登录看新订阅。  
   - 推荐：只能重置，列表不返回 uuid/token。

5. **只读用量**  
   列表是否展示各子账号 `u+d` / `transfer_enable`、在线设备。推荐：展示已用流量，方便企业自己看谁在用；设备数看缓存，二期再说。

6. **到期后能否继续添加子账号**  
   推荐：能添加、立刻是过期状态，避免合同谈完但套餐还没续上时加不了人。

7. **如何把现有用户收成子账号**  
   只支持「新建邮箱」。把已有独立套餐用户并入企业容易搞乱账单，超管若要做，单独开「迁移」且须先清掉该用户套餐。一期不做。

8. **流量重置日**  
   子账号 `expired_at` 与主账号相同，按套餐「到期日重置」时会同一天清零。是否符合预期：推荐是，当作企业统一账期。

9. **工单**  
   子账号自己的工单，企业管理员默认看不见。员工找企业管理员，管理员再找你们；或二期再做「本公司工单」。

10. **主账号被超管封禁**  
    推荐：主账号 `banned` 后不能登录管理，子账号**不自动暂停**（避免超管误封导致全公司掉线且无人能解）。超管要停一整企，改主账号 `expired_at` 或批量 banned。

## 12. 关键决定（已锁定）

| 决定 | 原因 |
|---|---|
| 不做流量池/设备池 | 避开节点下发与流量任务；额度按用户套餐字段即可 |
| 只用手动添加 | 不劫持 `invite_user_id` 返佣 |
| 主账号可使用 + 可管理 | 付费、登录、套餐都挂在 `v2_user` 上，避免空壳账号 |
| 到期跟随主账号 | 企业一份合同；续费只改主账号再同步 |
| 暂停 = `banned` | 已有登录拒绝 + 节点不下发 |
| 暂停占席位 | 暂停不是离职 |
| 续费走超管后台 | 与实际销售方式一致 |
| 不建组织表 | 主账号即组织，少一张表、少一次 join |

## 13. 合上游

本功能全部是 fork 增量：新列、新 Service、新路由，以及 `Admin\UserController@update`、`OrderService`、`OrderController@save` 的少量挂钩。合 `wyx2685/v2board` 时按 `docs/CHANGELOG.md` 惯例保留 `LOCAL:` 注释。不改 `Helper` 订阅拼装，不改 v2node。
